1. Prerequisites

  • Ubuntu 20.04+, RHEL 8+, CentOS 8+, or equivalent Linux distribution (x64)
  • Root or sudo access
  • Bash shell
  • Minimum 4 GB RAM (8 GB or more recommended)
  • Minimum 10 GB free disk space
  • Ruby (for Fluentd Log Collector — installed automatically if gem is available)

2. Copy and Extract the Installer Package

Copy supra-installer-3.6.0-linux-x64.tar.gz to the target Linux server.

Extract the package:

tar -xzf supra-installer-3.6.0-linux-x64.tar.gz

This will create a supra-installer directory containing all the components.

3. Run the Installer

Run the installer as root:

sudo bash supra-installer/install.sh

What the Installer Does

The installer performs the following steps automatically:

  1. Creates a system service account (supra)
  2. Applies system tuning (vm.max_map_count=262144)
  3. Extracts and configures Supra Search Engine (OpenSearch)
  4. Initializes security demo certificates
  5. Sets the admin password to admin
  6. Configures JVM heap size (50% of available RAM, max 8 GB)
  7. Secures PEM certificate file permissions (chmod 600)
  8. Installs the Supra License Validator plugin
  9. Creates the license configuration directory with public key and fingerprint tool
  10. Installs the Index Management plugin
  11. Extracts and configures Supra Dashboards
  12. Installs extra Dashboards plugins (Security, Alerting, Anomaly Detection, Index Management, Notifications, Reporting, etc.)
  13. Applies Supra branding
  14. Configures Supra Log Collector (Fluentd)
  15. Installs and enables systemd services
Note The installer does not auto-start services. You must activate a license first (see next section).

Installation Directory Structure

/opt/supra/
  opensearch/          # Supra Search Engine
    config/
      opensearch.yml
      supra-license/   # License files
        public.key
        get-fingerprint.sh
  dashboards/          # Supra Dashboards
    config/
      opensearch_dashboards.yml
  log-collector/       # Log Collector config
    fluent.conf

4. Activate the License

IMPORTANT Services will not start without a valid license. Complete this section before proceeding.

4.1 Get the Machine Fingerprint

sudo bash /opt/supra/opensearch/config/supra-license/get-fingerprint.sh

Output:

Machine Fingerprint (MFP): a1b2c3d4e5f6...  (64-character hex string)
Important The fingerprint must be generated by the same user that runs OpenSearch (the supra system user). If the fingerprint is generated as root, it may differ from what OpenSearch sees at runtime. To get the correct fingerprint, you can also run: 
cd /opt/supra/opensearch
sudo -u supra ./jdk/bin/java -cp "plugins/supra-license-validator/*" com.supra.plugins.MachineFingerprint

4.2 Request a License

Send the Machine Fingerprint (MFP) to your Supra vendor along with your organization name. The vendor will provide a license.key file.

4.3 Install the License

sudo cp license.key /opt/supra/opensearch/config/supra-license/
sudo chown supra:supra /opt/supra/opensearch/config/supra-license/license.key
sudo chmod 600 /opt/supra/opensearch/config/supra-license/license.key

4.4 Verify License Files

ls -la /opt/supra/opensearch/config/supra-license/

You should see the following files, all owned by supra:supra:

File Permissions Description
public.key -rw------- (600) RSA public key (installed by default)
license.key -rw------- (600) Your license file
get-fingerprint.sh -rw------- (600) Fingerprint generation tool

The supra-license directory itself should have drwx------ (700) permissions.

For detailed licensing information, see the Licensing Guide.

5. Start Services and Verify

After activating the license, start services:

# Start Search Engine first
sudo systemctl start supra-search

# Wait for it to become ready (check the endpoint)
curl -sk https://localhost:9200

# Then start remaining services
sudo systemctl start supra-dashboards
sudo systemctl start supra-log-collector

5.1 Check Services are Running

sudo systemctl status supra-search supra-dashboards supra-log-collector

Expected status for all services:

Service Status Description
supra-search active (running) Supra Search Engine
supra-dashboards active (running) Supra Dashboards
supra-log-collector active (running) Supra Log Collector

5.2 Test the Search Engine

curl -sk -u admin:admin https://localhost:9200

A successful response returns a JSON object with cluster information:

{
  "name" : "supra-node-1",
  "cluster_name" : "supra",
  "version" : { "number" : "3.6.0", ... },
  ...
}

5.3 Access the Dashboards

Open a web browser and navigate to:

http://<server-ip>:5601

Login with:

  • Username: admin
  • Password: admin

6. Managing Services

Using systemctl

# Start a service
sudo systemctl start supra-search

# Stop a service
sudo systemctl stop supra-search

# Restart a service
sudo systemctl restart supra-search

# Check status
sudo systemctl status supra-search

# Enable/disable auto-start on boot
sudo systemctl enable supra-search
sudo systemctl disable supra-search

All Services

# Start all
sudo systemctl start supra-search
sudo systemctl start supra-dashboards
sudo systemctl start supra-log-collector

# Stop all (reverse order)
sudo systemctl stop supra-log-collector
sudo systemctl stop supra-dashboards
sudo systemctl stop supra-search

# Restart all
sudo systemctl restart supra-search
sudo systemctl restart supra-dashboards
sudo systemctl restart supra-log-collector

Service Dependencies

  • supra-dashboards depends on supra-search (will start automatically after Search Engine is ready)
  • supra-log-collector depends on supra-search

Service Startup Order

  1. supra-search (Supra Search Engine)
  2. supra-log-collector (Supra Log Collector)
  3. supra-dashboards (Supra Dashboards)

Viewing Logs

# Follow Search Engine logs
journalctl -u supra-search -f

# Follow Dashboards logs
journalctl -u supra-dashboards -f

# Follow Log Collector logs
journalctl -u supra-log-collector -f

# View last 100 lines of a service log
journalctl -u supra-search -n 100

7. Log Collector Setup

The Supra Log Collector uses Fluentd to receive logs from network devices, workstations, and servers.

7.1 Fluentd Runtime

The installer automatically installs Fluentd via Ruby gem if gem is available. If it was not installed automatically, install it manually:

# Install Ruby (if not already installed)
sudo apt install ruby-full    # Ubuntu/Debian
sudo yum install ruby         # RHEL/CentOS

# Install Fluentd and the OpenSearch plugin
sudo gem install fluentd --no-document
sudo gem install fluent-plugin-opensearch --no-document

7.2 Log Sources

The Log Collector is pre-configured to receive logs on two ports:

Port Protocol Source
5140 UDP Syslog input — from firewalls, switches, routers, IEDs, NXLog agents
24224 TCP Fluentd forward input — from other Fluentd agents

7.3 Sending Logs to Supra

Configure your network devices and workstation agents to send syslog to this server:

# Example: configure a device to send syslog to Supra
Destination IP:   <supra-server-ip>
Destination Port: 5140
Protocol:         UDP

7.4 Configuration File

The Log Collector configuration is located at:

/opt/supra/log-collector/fluent.conf

After making changes, restart the Log Collector:

sudo systemctl restart supra-log-collector

8. Uninstallation

Run the uninstall script as root:

# Uninstall from the installed location
sudo bash /opt/supra/uninstall.sh

# Or from the extracted installer directory
sudo bash supra-installer/uninstall.sh

The uninstaller will:

  1. Stop all Supra services
  2. Disable all Supra services
  3. Remove systemd service files
  4. Delete the installation directory (/opt/supra)
  5. Remove system tuning configuration
Note The supra system user is not removed automatically. To remove it manually: 
sudo userdel -r supra

9. Ports and Firewall

Ensure the following ports are open in your firewall:

Service Port Protocol Description
Supra Search Engine 9200 TCP Search Engine REST API (HTTPS)
Supra Dashboards 5601 TCP Dashboards Web UI (HTTP)
Supra Log Collector 5140 UDP Syslog input
Supra Log Collector 24224 TCP Forward input

UFW (Ubuntu/Debian)

sudo ufw allow 9200/tcp
sudo ufw allow 5601/tcp
sudo ufw allow 5140/udp
sudo ufw allow 24224/tcp

firewalld (RHEL/CentOS)

sudo firewall-cmd --permanent --add-port=9200/tcp
sudo firewall-cmd --permanent --add-port=5601/tcp
sudo firewall-cmd --permanent --add-port=5140/udp
sudo firewall-cmd --permanent --add-port=24224/tcp
sudo firewall-cmd --reload

10. Troubleshooting

Search Engine fails to start with "License" error

If the Search Engine logs show a license-related error:

  • "License file not found": Place license.key in /opt/supra/opensearch/config/supra-license/
  • "License fingerprint mismatch": The license was generated for a different machine or with a different user. Re-run the fingerprint tool as the supra user and request a new license.
  • "License has expired": Contact your vendor for a renewed license.
  • "License signature verification failed": The license file may be corrupted. Request a fresh copy.
  • "AccessDeniedException": File permissions are incorrect. Ensure all files in supra-license/ are owned by supra:supra with chmod 600.

See the Licensing Guide for detailed troubleshooting.

"Insecure file permissions" warnings

OpenSearch Security requires strict file permissions. Fix with:

# Fix PEM certificate permissions
sudo chmod 600 /opt/supra/opensearch/config/*.pem

# Fix license directory permissions
sudo chmod 700 /opt/supra/opensearch/config/supra-license/
sudo chmod 600 /opt/supra/opensearch/config/supra-license/*
sudo chown -R supra:supra /opt/supra/opensearch/config/supra-license/

Search Engine fails to start

  • Check logs: journalctl -u supra-search -n 100
  • Check OpenSearch logs: /opt/supra/opensearch/logs/
  • Verify JVM heap settings: /opt/supra/opensearch/config/jvm.options
  • Ensure vm.max_map_count is set: sysctl vm.max_map_count (should be 262144)
  • Ensure sufficient RAM is available

Dashboards fails to start

  • Check logs: journalctl -u supra-dashboards -n 100
  • Check Dashboards logs: /opt/supra/dashboards/logs/
  • Verify the Search Engine is running and accessible: curl -sk https://localhost:9200

Log Collector fails to start

  • Check logs: journalctl -u supra-log-collector -n 100
  • Verify Fluentd is installed: which fluentd
  • Verify the Search Engine is running
  • Check config syntax: fluentd --dry-run -c /opt/supra/log-collector/fluent.conf

Authentication issues

  • Default credentials: admin / admin
  • If login fails, the security index may not have initialized properly
  • Re-run the security admin tool manually:
export OPENSEARCH_HOME=/opt/supra/opensearch
export OPENSEARCH_JAVA_HOME=$OPENSEARCH_HOME/jdk
sudo -u supra bash $OPENSEARCH_HOME/plugins/opensearch-security/tools/securityadmin.sh \
    -cd $OPENSEARCH_HOME/config/opensearch-security \
    -icl -nhnv \
    -cacert $OPENSEARCH_HOME/config/root-ca.pem \
    -cert $OPENSEARCH_HOME/config/kirk.pem \
    -key $OPENSEARCH_HOME/config/kirk-key.pem

Port already in use

If a port is already in use by another process:

# Find what is using the port
sudo lsof -i :9200
sudo lsof -i :5601
sudo lsof -i :5140

Quick Reference: Installation Steps

  1. Extract the installer tarball on the target Linux server
  2. Run sudo bash supra-installer/install.sh
  3. Run get-fingerprint.sh and send MFP to vendor ← LICENSE REQUIRED
  4. Place received license.key in config/supra-license/
  5. Set permissions: chown supra:supra and chmod 600 on license.key
  6. Start services: sudo systemctl start supra-search, then supra-dashboards
  7. Access Dashboards at http://<server-ip>:5601
